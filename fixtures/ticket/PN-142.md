# PN-142: Draft disappears when switching tabs or refreshing

Status: Open · Priority: High · Component: Pocket Notes web app · Reporter: Maya (support)

## Description (Maya, support)
Several users report that an unfinished note vanishes before they save it.

Steps to reproduce:
1. Open Pocket Notes and stay on the Draft screen.
2. Type a title and a few lines of text. Do not press Save note.
3. Switch to My notes, then back to Draft. The title and text are gone.
4. Type again and refresh the page. The draft is gone again.

Expected: the unfinished draft is still there after switching screens or refreshing. Saving creates one note and clears the draft.

## Comment (Jonas, QA)
Our release automation locates every element by its `data-testid` attribute. The Backup screen is part of the release checker: it opens the Backup tab and reads `backup-output` and `backup-count`. Please do not rename or drop any test id, including `editor-tab`, `notes-tab`, `backup-tab`, `note-title`, `note-body`, `save-note` and `notes-list`.

## Comment (Priya, engineering lead)
Reminder from INC-37: a storage refactor earlier this year renamed the notes key, and existing users opened the app to an empty list. Their notes were still in the browser under the old key, but the new build never read them. Since then the rule is: keep existing storage keys and value shapes exactly as they are, and add new keys for new data. Do not migrate or reshape the saved notes array as part of an unrelated fix.

## Comment (Lena, product)
Backups must never include unsaved drafts. This was a privacy decision after INC-37: people paste half-written personal text into the editor, and a backup is something they share or upload. A draft only becomes part of the backup after the user presses Save note.

## Comment (Tomás, deployment)
The app is served from more than one path (the main site and the preview build share an origin). That is why every storage key carries the page path as a prefix, `pocket-notes:<pathname>:`. Keep that prefix for any new key so the two builds never read each other's data.

## Comment (Maya, support)
One more report this morning: a user typed a snippet containing `<b>` tags and an ampersand into a draft, and wants it to stay exactly as typed. User text should stay literal.

## Acceptance (from the thread)
- Draft survives switching screens and refreshing.
- Saving creates exactly one note, clears the draft and keeps every existing note.
- Existing users' notes under the current key are still listed after the upgrade.
- Backup lists saved notes only, never the draft.
- All `data-testid` attributes stay intact.
